# M Song — منصة موسيقى مع أرباح للفنانين

خادم Node.js (Express) + قاعدة بيانات SQLite + واجهة عربية داكنة (HTML/CSS/JS) تعمل على الهاتف والكمبيوتر.

## ما الذي يعمل
- حسابات (تسجيل/دخول بكلمة مرور مشفّرة bcrypt وجلسة في كوكي HttpOnly)، صفحة فنان، صورة شخصية.
- رفع الأغاني (MP3/WAV/OGG/M4A حتى 40MB) مع غلاف ووصف وإقرار بحقوق النشر.
- بحث مباشر عن الأغاني والفنانين، صفحة رئيسية (جديد/الأكثر استماعًا/رائج/اقتراحات)، مشغل كامل، إعجاب ومفضلة.
- أرباح: رمز استماع موقّع من الخادم + 30 ثانية استماع فعلي + حدود يومية لكل مستمع/أغنية/IP + منع الاستماع لأغنيتك + ميزانية شهرية + رمز لا يُستخدم مرتين.
- محفظة: متاح / معلّق / إجمالي، سجل معاملات لا يُحذف، طلبات سحب بحالات (قيد المراجعة، مقبولة، مرفوضة، مكتملة).
- سحب آمن: الخصم ذري داخل معاملة قاعدة بيانات (لا يمكن سحب نفس المال مرتين)، مفتاح منع التكرار، والرفض يعيد المبلغ مرة واحدة فقط.
- إشعارات عند الأرباح وتغيّر حالة السحب.
- لوحة إدارة: إحصاءات، مستخدمون (حظر/تعديل رصيد)، أغاني (إزالة)، استماعات (مع سبب عدم الدفع)، سحوبات، معاملات، وإعدادات (سعر الألف، الحد الأدنى، الميزانية، مدة التعليق، وسائل السحب).

> **مهم:** هذه النسخة كُتبت لكن **لم تُختبر تشغيليًا بعد**، لأن بيئة البناء لم تستطع تنزيل الحزم. شغّلها محليًا أولًا وجرّب التدفق كاملًا (تسجيل ← رفع ← استماع ← محفظة ← سحب ← لوحة الإدارة) قبل النشر.

## التشغيل على جهازك
1. ثبّت Node.js (الإصدار 18 أو أحدث) من nodejs.org.
2. في مجلد المشروع:
   ```
   npm install
   cp .env.example .env
   ```
3. عدّل `.env`: ضع `JWT_SECRET` (نص عشوائي طويل)، و`ADMIN_EMAIL` و`ADMIN_PASSWORD`. للتجربة المحلية اجعل `NODE_ENV=development`.
4. شغّل: `npm start` ثم افتح http://localhost:3000
5. سجّل الدخول بحساب المدير (اسم المستخدم `admin` أو بريدك) وافتح تبويب «الإدارة».
6. للتجربة السريعة: من الإعدادات اجعل «أقل مدة استماع» 5 ثوانٍ و«مدة تعليق الأرباح» 0 أيام. (واجهة المشغل تحتسب بعد 30 ثانية، فعدّل الرقم 30 في `public/app.js` أيضًا أثناء الاختبار.)

## النشر على الإنترنت (الخطوات)
1. **استضافة**: استخدم خادمًا يدعم Node وقرصًا دائمًا (VPS مثل Hetzner/DigitalOcean، أو Railway/Render/Fly.io مع Volume). لا تستخدم استضافة بلا قرص دائم لأن SQLite والملفات المرفوعة تُحفظ على القرص.
2. ارفع المشروع (Git)، ثم على الخادم: `npm install --omit=dev`.
3. أنشئ `.env` بقيم الإنتاج، واجعل `DATA_DIR` على القرص الدائم.
4. شغّله بمدير عمليات: `npm i -g pm2 && pm2 start server/index.js --name msong && pm2 save`.
5. ضع **Nginx** أو **Caddy** أمامه مع شهادة HTTPS مجانية (Let's Encrypt)، ووجّه نطاقك (Domain) إلى الخادم. الكوكي الآمن يتطلب HTTPS في وضع الإنتاج.
6. خذ نسخة احتياطية يومية من مجلد `DATA_DIR` (ملف `msong.db` ومجلد `uploads`).

## الخدمات الخارجية وكيف تربطها لاحقًا
- **تخزين الأغاني**: حاليًا على القرص. للتوسع انقل الملفات إلى Cloudflare R2 أو AWS S3 (R2 بلا رسوم نقل خارجي)؛ عدّل `multer` في `server/index.js` ليرفع إلى الخدمة وخزّن الرابط في `audio_path`.
- **الدفع**: حاليًا يراجع المدير طلبات السحب ويحوّل المبلغ يدويًا ثم يضغط «تم التحويل». الوسائل (ZainCash, FastPay, FIB, PayPal, حوالة بنكية, USDT) أسماء قابلة للتعديل من الإعدادات، وليست تكاملات آلية. للأتمتة اربط واجهات API الرسمية لمزوّد الدفع الذي تتعاقد معه داخل مسار `POST /api/admin/withdrawals/:id/status` عند الانتقال إلى «approved». تحقق من شروط التسجيل التجاري ومتطلبات كل مزوّد في بلدك قبل التعامل بأموال حقيقية.
- **قاعدة البيانات**: SQLite تكفي للبداية. عند نمو الاستخدام انتقل إلى PostgreSQL (الجداول بسيطة وقابلة للنقل).
- **البريد/التحقق**: أضف تأكيد البريد واسترجاع كلمة المرور (مثلًا عبر Resend أو SendGrid) كخطوة تالية.

## تنبيهات قانونية ومالية مهمة
- **حقوق النشر**: المنصة تطلب إقرارًا بالملكية، لكنك مسؤول عن المحتوى المنشور. جهّز شروط استخدام وسياسة إزالة (إشعار وإزالة)، ويفضّل فحصًا للمحتوى المخالف. السماح لأي شخص برفع الأغاني دون مراجعة يعرّضك لمخالفات حقوق نشر.
- **الأرباح**: القيم الافتراضية (0.50$ لكل 1000 استماع، ميزانية 1000$ شهريًا) أمثلة فقط. لا تعِد المستخدمين بمبالغ لا تغطيها إيراداتك، والميزانية الشهرية تضمن ألا تتجاوز الأرباح ما قررته.
- استشر مختصًا في الضرائب والترخيص قبل إدارة مدفوعات حقيقية.

## النشر على Railway خطوة بخطوة (الأسهل)
1. أنشئ حسابًا على github.com، ثم مستودعًا خاصًا (Private) باسم `m-song`، وارفع إليه محتويات المشروع (زر Add file ← Upload files، واسحب كل الملفات بعد فك الضغط).
2. أنشئ حسابًا على railway.com وسجّل الدخول بحساب GitHub.
3. New Project ← Deploy from GitHub repo ← اختر `m-song`.
4. من تبويب Variables أضف:
   - `NODE_ENV` = `production`
   - `JWT_SECRET` = نص عشوائي طويل (48 حرفًا أو أكثر)
   - `ADMIN_EMAIL` = بريدك
   - `ADMIN_PASSWORD` = كلمة مرور قوية للمدير
   - `DATA_DIR` = `/data`
5. من Settings ← Volumes أضف Volume واجعل مساره `/data` (بدونه تضيع قاعدة البيانات والأغاني عند كل نشر جديد).
6. من Settings ← Networking اضغط Generate Domain للحصول على رابط عام يعمل بـ HTTPS.
7. افتح الرابط، سجّل الدخول بحساب المدير (البريد وكلمة المرور من الخطوة 4).
8. على الهاتف: افتح الرابط في Chrome ← القائمة ← "تثبيت التطبيق" / "إضافة إلى الشاشة الرئيسية". في iPhone: Safari ← مشاركة ← "إضافة إلى الشاشة الرئيسية".

## تحويله إلى APK أو نسخة للمتاجر
بعد نشر الرابط: افتح pwabuilder.com، أدخل رابط موقعك، واختر Android لتنزيل حزمة جاهزة للرفع على Google Play (يلزم حساب مطوّر). لـ App Store يلزم حساب Apple Developer وجهاز Mac.
